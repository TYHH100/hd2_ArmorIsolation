# Helldivers 2 护甲相关分析

分析日期：2026-09-19。对象：`G:\AppData\SteamLibrary\steamapps\common\Helldivers 2`。

后续更新：已完成运行时护甲外观代码分析，见 [护甲外观执行流程](armor-appearance-execution.md)。下文保留第一轮离线分析的证据范围；外观原生函数和运行时套装数据以新报告为准，减伤公式仍未还原。

结论：护甲需要分别看套装配置、外观资源、被动修饰器和受击结算。本次已核对本地文件和模型资源共用实例；磁盘 DLL 受保护，尚未还原护甲减伤函数或确定其运行时偏移。

## 4. 外观、部件与共用关系

社区结构给出的关系是：

```text
HelldiverCustomizationKit
  -> 套装标识 / 被动标识 / Archive
  -> Body：体型分组
  -> Piece：Unit 资源标识、部位、部件类型、材质引用
  -> 本地资源包中的 unit / material / texture 等资源
```

套装分为护甲、头盔、披风。部位包含头盔、披风、躯干、髋部、左右腿、左右臂、左右肩。部件还区分护甲片、内衬和附件，并带有体型及轻中重分类。

外观并非只有一个模型路径：部件还引用材质 LUT、图案 LUT、披风渐变、贴花等资源。因此同一个 Unit 可以与不同材质配置组合。修改共享 Unit 或共享材质可能影响其他套装；实际覆盖范围还受资源解析和补丁加载顺序影响。

来源：[Filediver 套装解析代码](https://github.com/xypwn/filediver/blob/70f3447cd415c964e0bd29ff0770b97a4d0f160d/datalibrary/armor_sets.go)。

## 5. 属性与被动

套装通过 `Passive` 标识关联 `HelldiverCustomizationPassiveBonusSettings`。被动包含多个修饰器，每项有目标标识、操作类型、数值和说明文本引用。

| 操作 | 结构含义 | 解读注意 |
| --- | --- | --- |
| Set | 设置目标值 | 数值为 0 不等于“没有效果” |
| Add | 增量 | 单位取决于目标字段，不能统一解释为百分比 |
| Multiply | 倍乘 | `0.5` 是目标量乘 0.5，是否等于减伤 50% 取决于目标量 |
| Time | 时间类参数 | 与加法、乘法分开记录 |

社区快照中有 31 条被动记录，还存在独立的 `StatModifiers` 数组；其中部分字段在解析器里仍用未知字段名表示。

例如被动 ID 1 的某个修饰器为 `Add 1.0`，被动 ID 3 含 `Multiply 0.7` 和 `Multiply 0.5`。这些是社区快照读数；本次未解析其目标哈希含义，不能据此声称找到了本机额外护甲或爆炸减伤公式。

特别注意：`Piece.Weight` 是部件级字段。所查 SC-34 套装记录中，不同部件同时出现轻、中、重分类；不能取任意一个部件的 Weight 直接推算整套护甲评级、速度或耐力。

来源：[Filediver 被动解析代码](https://github.com/xypwn/filediver/blob/70f3447cd415c964e0bd29ff0770b97a4d0f160d/datalibrary/passive_bonuses.go)。

## 6. 装甲与伤害结算

社区解析结构中，攻击侧包含普通伤害、耐久伤害、四档角度穿透参数和伤害元素。防御侧的健康组件按受击区域记录装甲、装甲角度检查、最大装甲、伤害倍率、耐久伤害权重、区域生命值以及伤害传递至主生命值的比例等信息。

这里至少应区分三种概念：

| 概念 | 所属层次 | 不能直接推出的结论 |
| --- | --- | --- |
| 玩家面板护甲评级 | 装备属性与显示 | 不能直接作为受击区域的装甲等级 |
| `DamageableZoneInfo.Armor` | 通用受击区域组件 | 不能直接解释为面板护甲值或固定减伤百分比 |
| `Piece.Weight` | 外观部件描述 | 不能直接确定整套装备属性 |

`DamageMultiplier` 和 `DamageMultiplierDPS` 在社区解析器中是枚举，包含 Critical、Normal、Reduced 等类别，不是已经确定的浮点乘数。上述健康组件是通用结构，不能把某个敌人的区域参数直接套用于玩家护甲。

这些数据支持按“攻击配置 -> 命中区域 -> 穿透及伤害修饰 -> 区域/主生命值”拆分调查，但该箭头只表示分析依赖，不是已还原的执行顺序。

尚未确认：

- 被动、姿态、部位、元素抗性等修饰的叠加顺序。
- 穿透不足、相等和高于装甲时，本版本使用的精确倍率。
- 面板属性与实战状态的同步方式、客户端和服务端职责。
- 对应本机版本的原生函数 RVA、调用关系和结构体内存偏移。

来源：[受击区域与健康组件](https://github.com/xypwn/filediver/blob/master/datalibrary/health_component.go)、[伤害配置](https://github.com/xypwn/filediver/blob/master/datalibrary/damage_settings.go)、[伤害倍率枚举](https://github.com/xypwn/filediver/blob/master/datalibrary/enum/damagemultiplier.go)。这些结构源码于本次在线检查，不能将源码字段顺序直接当成本机内存布局。

## 7. 后续定位顺序

1. 外观问题：以某一套装为入口，确定体型、部位和实际被替换的 Unit，再检查共享 Unit、材质和纹理。已有本地共用实例可作基线。
2. 属性问题：取得同版本可读配置，解析套装到被动及属性修饰的关联，明确每个目标标识的语义。
3. 原生公式：取得同版本运行时模块或有效转储，核对版本后，从配置注册、读取位置和受击处理交叉引用逐步追踪。
4. 行为验证：每次固定一类伤害和命中部位，逐项比较装备、被动及姿态，避免同时改变多个条件。

磁盘保护段、旧版本偏移和社区结构都不足以单独证明本版本的原生结算实现。本轮结论止于文件结构、社区字段解释和已经核对的本地资源关系。
