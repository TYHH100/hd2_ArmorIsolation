# B-01 GPU 磁盘段去重的证据与边界

日期：2026-09-19。**此方向已停止，不作为当前交付方案。** 用户随后明确要求同模组内部共享材质和纹理；下文是已经放弃的 GPU 磁盘段去重调查，不代表正在使用的成品布局。本次仅检查限定样本的 TOC、既有本地读取器和 Filediver 格式实现，没有修改游戏，也没有继续展开原生加载器逆向。

## 问题拆分

B-01 八个 Kit 各自拥有私有材质和纹理 ID，生成了 204 个独立资源记录。重复写入相同 GPU 字节导致最初 `.gpu_resources` 约 2.09 GiB。可以分别讨论三件事：

1. **资源身份**：204 个 `(类型, 私有 ID)` 及 Kit 引用必须保持独立。
2. **磁盘存储**：相同的只读初始字节是否可以由多个 TOC 条目指向同一文件区间。
3. **运行时存储**：GPU 缓冲偏移、最终纹理对象及显存分配是否独立。

磁盘去重可以在表示上保留资源身份与独立缓冲偏移，但是否被当前游戏加载器接受，还需要游戏实测。不能因为文件变小就宣称显存占用同步下降。

## 2. 外部格式实现确认了什么

Filediver 固定提交 `70f3447cd415c964e0bd29ff0770b97a4d0f160d` 的 [archive.go:92](https://github.com/xypwn/filediver/blob/70f3447cd415c964e0bd29ff0770b97a4d0f160d/stingray/archive.go#L92) 把 `Offsets[main,stream,GPU]`、`MainBufferOffset`、`GPUBufferOffset`、`Sizes` 分成独立字段。对应本地 `<7Q6I>` TOC 中的第 2/3/4、5、6、7/8/9 项。

[fat_edition.go](https://github.com/xypwn/filediver/blob/70f3447cd415c964e0bd29ff0770b97a4d0f160d/stingray/fat_edition.go) 中，`openDataDirFat` 使用 `Offsets` 和 `Sizes` 建立资源位置，`readNBytesFat` 对文件执行 `Seek(offset)` 后读取指定长度；这个提取路径不使用 GPUBufferOffset。因而提取器按每个条目读出相同磁盘区间是可表示、可读取的，**不等于游戏原生加载器已确认接受**。

同文件头中的 [ApproxGPUSize 定义](https://github.com/xypwn/filediver/blob/70f3447cd415c964e0bd29ff0770b97a4d0f160d/stingray/archive.go#L71) 仍标为近似大小。本地已验证原版按每条资源 GPU 大小向上对齐 256 后累计；该字段不应改成去重后的磁盘文件长度。现有原生笔记只覆盖资源查找/就绪与外观装配，没有证明磁盘加载器对重复区间的调度方式。

## 3. 已放弃临时候选的只读结构核对

本次调查期间主实现曾生成 GPU 段去重临时候选。以下为当时工作区文件快照，现有输出可能已被后续方案替换，不能作为当前产物数值：

- `.gpu_resources` 磁盘长度：`304244608` 字节。
- 204 个 TOC 条目的 GPU 原始长度之和：`2249513488` 字节。
- 各 GPU 长度逐项向上对齐 256 的总和及头部 GPU buffer 字段：均为 `2249523712`。
- 例：纹理 `01ed1c6a445f62d9` 和 `03bdf3d4fc903deb` 的磁盘区间都是 `offset=650496,size=262144`，但 GPUBufferOffset 分别为 `0` 与 `67371008`。

这说明候选在 TOC 层保留了独立缓冲地址，仅复用磁盘字节。它是**新生成候选的内部证据**，不能列为已运行游戏的格式先例，也不能证明 GPU 对象身份或显存大小。

## 4. 当时的实验条件与验证边界

若以后重新讨论 GPU 磁盘段去重，仍需作为实验验证。去重键至少包含有效长度和内容 SHA-256，只合并完全相同字节；不同区间部分重叠仍应拒绝。必须保留全部资源 ID、私有引用、各自的 GPUBufferOffset 与原头部内存大小计算，并按每个引用重新读取/核对 payload。材质主数据已经按 Kit 改写，不能依据原始来源直接合并。

保留展开布局的可重建选项，发生加载失败时以同样 204 个 ID 重建展开文件做对照，不需要长期保留两份大文件。若去重版失败而展开版成功，问题才能缩小到文件布局；若两版都失败，仍需检查配置和资源加载。

游戏验收应先看 204 资源就绪及八 Kit 引用发布，再看八套目标、混搭和非目标对照。加载成功仍不等于显存优化成立；本方案当前目标是节省磁盘重复数据并保留隔离效果。尚无依据把该布局作为无需实验的通用打包默认。
